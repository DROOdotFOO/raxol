# Changelog

## 0.1.0 - Unreleased

- Add the standalone package and its fail-closed policy workflow. Policy files are parsed as bounded data rather than evaluated as Elixir, initialization publishes a complete file atomically without replacing an existing destination, and prompting is available only in interactive terminals (with deterministic process-shell coverage). Decimal 3 avoids EEF-CVE-2026-32686.
- `Raxol.Broker.Supervisor` (#1172), a `:rest_for_one` root to start from your own tree, with `Raxol.Broker.Journal` first (options under `:journal`). The package still has no application callback, so nothing starts until you start it.
- `Raxol.Broker.PolicyFile.new/2` builds the complete restrictive policy from the two required caps; `mix raxol.broker.init` uses it. Terminal prompts accept the trimmed entered line, and EOF raises `Mix.Error` without writing. The staging file is created with mode 0600 before it is written, so the published policy is mode 0600.
- `PolicyFile.load/1` rejects symlinks and files that `Raxol.Agent.OperatorFile.trusted?/1` refuses (owner, mode, or parent directory) with `{:error, {:untrusted_file, path, reason}}`, returns `{:error, {:parse_error, path, :invalid_utf8}}` for invalid UTF-8, and limits `ask_timeout` to 1..4_294_967_295 ms.
- Robinhood sign-in and session (#1173). `Raxol.Broker.Login.run/1` runs `Raxol.Agent.Auth.Flow.run(:robinhood, ...)` (pinned endpoints, verified discovery, dynamic client registration, PKCE, `state` and RFC 9207 `iss` checks on a `127.0.0.1` loopback callback) and stores the credential with `Raxol.Broker.CredentialStore`.
- `Raxol.Broker.CredentialStore` writes a versioned AES-256-GCM envelope (`{"v":1,"nonce","ct","tag"}`, random 96-bit nonce per write, AAD binding the version and purpose) to `~/.raxol/broker/robinhood.credential` (`$RAXOL_BROKER_CREDENTIAL` or `:path` override): exclusive same-directory staging file set to 0600 before it is written, fsync, rename, directory fsync, and a refusal for a symlink at the target. Reads require a regular file (via `lstat`) owned by this account with no group or other bits, at most 64 KiB, with the same inode once opened; truncated, malformed or tampered files are `{:error, :corrupt_store}` and an unknown version is `{:error, {:unsupported_version, v}}`.
- The wrapping key is held by `Raxol.Broker.KeyProvider`: 1Password when `op` is installed (`KeyProvider.OnePassword`, an `op://` reference under `robinhood_broker_key`), otherwise the macOS login keychain (`KeyProvider.Keychain`, written through `security -i` on stdin so the key is never on argv; an existing item is never replaced). Elsewhere the store refuses with `{:error, {:keychain_unavailable, :unsupported_os}}`; nothing is ever written in plaintext or beside its key.
- `Raxol.Broker.MCP.Client` owns one unregistered `Raxol.MCP.Client` for `https://agent.robinhood.com/mcp/trading`, caches the tool list on connect, refreshes before `expires_at`, and on a 401 runs one refresh shared by every waiting caller, persists the rotated credential before using it, restarts the inner client with the new bearer and retries each request once. A second 401 is `{:error, :unauthorized}` for every caller, with the inner client stopped and the process still running; a 403 never refreshes. `call/3` allows only the tools the server annotates read-only (`get_*`, `preview_scan`, `run_scan`, `search`) and answers anything else `{:error, {:tool_denied, name}}` without a request. `format_status/1` and `Inspect` hide the credential.
- The inner client pins the 2025-06-18 era: the live endpoint refuses `server/discover` with a plain-text 400 (observed 2026-10-03), so the probe is never sent. A token rejected at the `initialize` handshake now reaches the refresh path after one attempt rather than after the connect budget, by which point the inner client had opened the origin breaker.
- `Raxol.Broker.Intent` and `Raxol.Broker.Policy.evaluate/2` (#1176). Intent constructors validate symbols, amounts and a required provenance and return `{:error, reason}` instead of raising. `evaluate/2` is pure: it reads only the intent and a `Raxol.Broker.Policy.Context` and returns `{:allow, intent}`, `{:ask, [{rule_id, prompt}]}` or `{:deny, {rule_id, detail}}`, with twelve rules run through `Raxol.Agent.Authorization.Engine` (deny over ask over allow): pricing, symbol allow/deny lists, order type, after-hours market orders, drawdown breaker, order rate, per-order and daily notional caps (inclusive), post-trade position weight, review warnings, untrusted provenance, and `llm_ask_above`. Missing context denies; cancels are always allowed.
- The policy file gains `advanced_orders`, `symbols_allow`, `symbols_deny`, `max_orders_per_minute` and `drawdown_halt`, and `order_types` accepts `:stop_limit` and `:stop_market`. Every key is still required, so a policy written by an earlier `mix raxol.broker.init` fails to load with `{:missing_key, :advanced_orders}`; rerun the task in an empty directory or add the keys with their defaults.
- `Raxol.Broker.Journal`, the hash-chained decision journal (#1177): one `Raxol.Agent.Journal.FileStore` journal opened with `chain: true, private: true` at `~/.raxol/broker/journal` (`$RAXOL_BROKER_JOURNAL` or `:path`), directories 0700 and files 0600; a symlinked, foreign-owned or shared directory is refused. Each decision is a group of records sharing a `group_id`: intent, policy context snapshot, verdicts (`:pre_review`, `:post_review`, each with the rule ids in force), review response, `{:approval, :approved | :declined, by}` for a human answer to an ASK, `{:placing}`, and a terminal order response (`:placed`, `:failed` or `:unknown`), DENY verdict, declined approval or close. `open_group/2` writes the intent and context before any review or order call, `append_to_group/2` adds records as they happen, and `append_group/1` writes a whole group in one Writer call with the same validation. Every record is synced before the call returns, and nothing may follow a group's terminal record.
- `{:placing}` is the write-ahead point for the order call: the journal prices the order from the group's own intent and context and refuses one it cannot price (`{:error, {:unpriced_order, reason}}`); an order response without it is refused (`{:not_placing, id}`), and after it only an order response or a close is accepted. A close after `placing` records an unknown outcome. Review and order responses are recorded as given, with floats written as decimal strings, so a real order is never refused for its response's shape.
- On start the journal verifies its chain in one pass. A damaged journal keeps the process up and answers every append and query with `{:error, {:journal_damaged, offset}}`. On a healthy one, a group left open by a crash is closed: DENY `crash_before_verdict` when it has no `placing` record, otherwise `crash_outcome_unknown`, which keeps counting because the order call may have gone out. `verify/1` re-walks the chain on disk (appends wait behind it) and marks the journal unusable on any result but `:ok`; arming (#1179) is expected to require it. The journal traps exits, closes its Writer on shutdown, links to a Writer it joined, and stops when that Writer dies, so its supervisor restarts it.
- Queries read an ETS index built on start and kept current: an order counts toward `today_notional(since)` and `orders_last_minute(now)` from the moment its `placing` record is written, at the notional recorded there, and stops only when its order response says `:failed`; cancels and groups that never reached `placing` never count, and the live and rebuilt indexes agree. `realized_pnl_today(since)` sums the broker-reported P&L of `append_fill/1` records. The exchange-day boundary is the caller's (a UTC instant), so the context builder (#1185) owns the New York calendar.
- `Raxol.Broker.Journal.Codec` round-trips `%Intent{}` and `%Policy.Context{}` through JSON (Decimals as exact strings, atoms only from fixed lists or existing atoms), so a later replay can re-run `Policy.evaluate/2`; verdict details are encoded one way. `Policy.notional/2` is now public; `placing` uses it to price each order once.
- `mix raxol.broker.replay --date YYYY-MM-DD [--journal PATH]` prints each group opened that UTC day in journal order: intent, context, every rule's verdict for each policy pass (`pass` before the denying rule, `not run` after it), review, approval, placing, order, and outcome (including `IN FLIGHT` and counted `UNKNOWN`), then that day's fills. Every line passes through one escape step, so control characters in recorded text (C0, DEL, C1) print as `\uXXXX` and invalid UTF-8 as `\xNN`. It reads without the writer lock and refuses a journal whose chain does not verify, naming the offset. The README documents what to do with a damaged journal.
- `Raxol.Broker.Executor`, the one order path (#1178): `run/4` opens the group, journals the pre-review verdict, calls the order's `review_*` tool, journals the review, re-runs `Policy.evaluate/2` with the review's warnings, and on ALLOW journals `placing` and calls the order tool through `Raxol.Broker.Executor.Place`, journaling the response as `:placed`, `:failed` (`isError`, a JSON-RPC parse, request, method or params error, or a client error that provably sent nothing) or `:unknown` (timeout, transport failure, any other error). Any review warning, or a review response that cannot be read, turns ALLOW into ASK (`:review_warning`); `{:ask, group_id, prompts}` parks the group until `approve/4` (re-reads the counters, journals the approval, re-runs the policy, then places), `decline/3` or `close/3`. A bad approver or reason raises in the caller and leaves the group parked. The review call runs in a task, so `parked/2` answers during it.
  - The `:policy` start option (required, checked with `PolicyFile.validate/1`) replaces the context's `policy`; `today_notional`, `orders_last_minute` and `review_warnings` are replaced too. Quotes, positions, portfolio values and `market_session` stay caller-supplied until #1185.
  - The daily window defaults to the last 24 hours; `:day_start` must be a `DateTime` within it, otherwise `{:error, {:context, {:invalid_day_start, value}}}` before any group opens.
  - Any journal or review error before `placing` means no order. Once the order call is made the result is `{:ok, map}`; `journaled: false` with `journal_error` means the response could not be recorded.
  - The executor traps exits: if the port's client dies it stays up and later runs and approvals return `{:error, {:port_down, reason}}` before opening anything.
- `Raxol.Broker.Executor.Place` is the only module naming an order tool (`place_equity_order`, `cancel_equity_order`), enforced by a grep test. It refuses without an opaque `Raxol.Broker.Executor.ReviewReceipt` (HMAC-SHA256 under a per-start executor key over a fingerprint of the whole intent, the group id and a nonce). Each place sends `ref_id`, a UUID derived from the intent id; an intent id with a `placing` whose outcome is not `:failed` returns `{:ok, :duplicate}` without a call, across restarts (`Raxol.Broker.Journal.placing_for_intent/2`).
- `Raxol.Broker.Journal.claim/1`: one executor per journal. A starting executor claims the journal and a second gets `{:journal_claimed, pid}`. The journal refuses `placing` from a non-claimant, for a group without a review and an ALLOW or approval after it, and for an intent that already has a live `placing` in another group.
- Order tools go through `Raxol.Broker.Executor.Port`, a write-capable session separate from the read-only `Raxol.Broker.MCP.Client`; `Port.MCP` wraps an unregistered `Raxol.MCP.Client`. Only `mode: :dry_run` runs, and the session must carry `sandbox: true` and a URL that is not on `robinhood.com`, or it is refused as live before connecting; `mode: :armed` is `{:error, :not_armed}` until arming (#1179). Only equity orders and cancels are mapped until #1174.
- `Raxol.Broker.Journal.open_group/4` takes `mode:`, stored on the intent record and shown by replay; `open_groups/1` lists groups without a terminal record, which a starting executor closes as `executor_restarted`.
- Depends directly on `raxol_mcp`, `mint`, `castore`, `req` and `jason`.
