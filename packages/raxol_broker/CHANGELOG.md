# Changelog

## 0.1.0 - Unreleased

- Add the standalone package and its fail-closed policy workflow. Policy files are parsed as bounded data rather than evaluated as Elixir, initialization publishes a complete file atomically without replacing an existing destination, and prompting is available only in interactive terminals (with deterministic process-shell coverage). Decimal 3 avoids EEF-CVE-2026-32686.
- `Raxol.Broker.Supervisor` (#1172), a `:rest_for_one` root to start from your own tree, with `Raxol.Broker.Journal` first (options under `:journal`) and, when `:executor` options are given, `Raxol.Broker.Executor` after it, always pointed at that journal (a different `:journal` makes `start_link/1` return `{:error, {:journal_mismatch, given}}`) and named `Raxol.Broker.Executor` by default. A journal crash restarts the executor, which closes the groups it left open; its child spec carries the executor's `shutdown`. The package still has no application callback, so nothing starts until you start it.
- `Raxol.Broker.PolicyFile.new/2` builds the complete restrictive policy from the two required caps; `mix raxol.broker.init` uses it. Terminal prompts accept the trimmed entered line, and EOF raises `Mix.Error` without writing. The staging file is created with mode 0600 before it is written, so the published policy is mode 0600.
- `PolicyFile.load/1` rejects symlinks and files that `Raxol.Agent.OperatorFile.trusted?/1` refuses (owner, mode, or parent directory) with `{:error, {:untrusted_file, path, reason}}`, returns `{:error, {:parse_error, path, :invalid_utf8}}` for invalid UTF-8, and limits `ask_timeout` to 1..4_294_967_295 ms.
- Robinhood sign-in and session (#1173). `Raxol.Broker.Login.run/1` runs `Raxol.Agent.Auth.Flow.run(:robinhood, ...)` (pinned endpoints, verified discovery, dynamic client registration, PKCE, `state` and RFC 9207 `iss` checks on a `127.0.0.1` loopback callback) and stores the credential with `Raxol.Broker.CredentialStore`.
- `Raxol.Broker.CredentialStore` writes a versioned AES-256-GCM envelope (`{"v":1,"nonce","ct","tag"}`, random 96-bit nonce per write, AAD binding the version and purpose) to `~/.raxol/broker/robinhood.credential` (`$RAXOL_BROKER_CREDENTIAL` or `:path` override): exclusive same-directory staging file set to 0600 before it is written, fsync, rename, directory fsync, and a refusal for a symlink at the target. Reads require a regular file (via `lstat`) owned by this account with no group or other bits, at most 64 KiB, with the same inode once opened; truncated, malformed or tampered files are `{:error, :corrupt_store}` and an unknown version is `{:error, {:unsupported_version, v}}`.
- The wrapping key is held by `Raxol.Broker.KeyProvider`: 1Password when `op` is installed (`KeyProvider.OnePassword`, an `op://` reference under `robinhood_broker_key`), otherwise the macOS login keychain (`KeyProvider.Keychain`, written through `security -i` on stdin so the key is never on argv; an existing item is never replaced). Elsewhere the store refuses with `{:error, {:keychain_unavailable, :unsupported_os}}`; nothing is ever written in plaintext or beside its key.
- `Raxol.Broker.MCP.Fake` (#1175): Robinhood's MCP server in process, for tests, dry runs and backtests with no account and no network. It is raxol_mcp's legacy-era reference server behind the transport's `:exchange` seam, serving the recorded tool list (moved to `priv/robinhood/tools_list.json`) plus `get_equity_positions`, `get_equity_orders` and `get_alert_log`. A scenario sets quotes, positions, alerts, review warnings, rejected symbols and the order-state schedule; `place_*` is idempotent on `ref_id`. Faults (`{:http, status}`; `:malformed`, which leaves the call unanswered until its timeout; `{:slow, ms}`; `:closed`, reported as `{:error, {:transport, :closed}}` like the real exchange) match a tool or method and are consumed in order. Exchanges are recorded on arrival (`:pending` until answered). `session/1` is an `Executor.Port.MCP` spec; `client_opts/2` is a complete read-only session that never reads the stored credential and can never refresh (a 401 locks out); `mcp_opts/1` is only its `:mcp` part. A served tool without an answer fails with a JSON-RPC error rather than a made-up shape. It replaces the test-only `OrderServer`. `raxol_broker` now depends on `plug` directly.
- `Raxol.Broker.MCP.Client` retries a `429`, `502`, `503` or `504` with jittered doubling backoff (`:backoff` option: `:base_ms` 500, `:max_ms` 8000, `:retries` 3; invalid values stop `start_link/1` with `{:invalid_backoff, value}`), then returns the status. A retry is not sent when its delay would pass the caller's `call/4` timeout, when one more failure would open the session's circuit breaker, or when the caller has exited; a throttled call never answers `:breaker_open`. A connect throttled at the `initialize` handshake or its `tools/list` (including the reconnect after each refresh) is retried the same way on a new inner client, at most `:retries` times in a row and without the breaker check, since each inner client starts on fresh breaker tables; a queued caller whose timeout the next delay would pass is answered at once, the others wait, and when the retries run out every queued caller gets `{:error, {:http, status}}` (for a throttled handshake too, rather than `{:connect_failed, {:initialization_failed, {:http, status}}}`). A throttled request keeps its one post-refresh retry, so a 401 after a 429 locks out instead of refreshing again. Every call on that session is read-only; order tools never take this path, so a throttled order is not re-sent. `Retry-After` is not read, because the transport drops the headers of a non-2xx response. `Raxol.MCP.CircuitBreaker.failure_threshold/1` exposes the threshold it applies.
- The Fake gates on the bearer: with the `:accept` scenario option (or `Fake.accept/2` at runtime) a request whose `Authorization: Bearer` token is not listed gets Robinhood's recorded invalid-token 401; unset, every token is accepted, so `client_opts/2` sessions are unchanged. `Fake.forbid_calls/1` answers every `tools/call` 403. `server/discover` always gets Robinhood's recorded plain-text 400, so a spec not pinned to the legacy era fails against the Fake as it does against Robinhood (`session/1` and the broker client are pinned). The two recordings moved from `test/fixtures/auth` to `priv/robinhood/` and are embedded at compile time. Headers are never recorded, so `requests/1` never holds a token. The session tests now run against the Fake, and the second test-only MCP server that duplicated it is gone.
- `Raxol.Broker.MCP.Client` retries a `429`, `502`, `503` or `504` with jittered doubling backoff (`:backoff` option: `:base_ms` 500, `:max_ms` 8000, `:retries` 3; invalid values stop `start_link/1` with `{:invalid_backoff, value}`), then returns the status. A retry is not sent when its delay would pass the caller's `call/4` timeout, when one more failure would open the session's circuit breaker, or when the caller has exited; a throttled call never answers `:breaker_open`. A throttled request keeps its one post-refresh retry, so a 401 after a 429 locks out instead of refreshing again. Every call on that session is read-only; order tools never take this path, so a throttled order is not re-sent. `Retry-After` is not read, because the transport drops the headers of a non-2xx response. `Raxol.MCP.CircuitBreaker.failure_threshold/1` exposes the threshold it applies.
- `Raxol.Broker.MCP.Client` owns one unregistered `Raxol.MCP.Client` for `https://agent.robinhood.com/mcp/trading`, caches the tool list on connect, refreshes before `expires_at`, and on a 401 runs one refresh shared by every waiting caller, persists the rotated credential before using it, restarts the inner client with the new bearer and retries each request once. A second 401 is `{:error, :unauthorized}` for every caller, with the inner client stopped and the process still running; a 403 never refreshes. `call/3` allows only the tools the server annotates read-only (`get_*`, `preview_scan`, `run_scan`, `search`) and answers anything else `{:error, {:tool_denied, name}}` without a request. `format_status/1` and `Inspect` hide the credential.
- The inner client pins the 2025-06-18 era: the live endpoint refuses `server/discover` with a plain-text 400 (observed 2026-10-03), so the probe is never sent. A token rejected at the `initialize` handshake now reaches the refresh path after one attempt rather than after the connect budget, by which point the inner client had opened the origin breaker.
- `Raxol.Broker.Intent` and `Raxol.Broker.Policy.evaluate/2` (#1176). Intent constructors validate symbols, amounts and a required provenance and return `{:error, reason}` instead of raising. `evaluate/2` is pure: it reads only the intent and a `Raxol.Broker.Policy.Context` and returns `{:allow, intent}`, `{:ask, [{rule_id, prompt}]}` or `{:deny, {rule_id, detail}}`, with twelve rules run through `Raxol.Agent.Authorization.Engine` (deny over ask over allow): pricing, symbol allow/deny lists, order type, after-hours market orders, drawdown breaker, order rate, per-order and daily notional caps (inclusive), post-trade position weight, review warnings, untrusted provenance, and `llm_ask_above`. Missing context denies; cancels are always allowed.
- `Raxol.Broker.Plain` is the data boundary for caller input. It accepts binaries, atoms, integers, proper lists and tuples, non-struct maps, `Decimal` (sign 1 or -1, a coefficient of at most 40 digits and an exponent in -40..40, rebuilt) and ISO `DateTime` (rebuilt), and refuses floats, pids, refs, ports, functions, improper lists, other structs and nesting deeper than 32. It checks by pattern matching only, so no caller protocol implementation (Enumerable, Inspect, String.Chars) ever runs. `Intent.normalize/1` and `Policy.Context.normalize/1` accept any term and return a freshly built struct or `{:error, :not_an_intent | :not_a_context | {:invalid, field} | {:not_plain, path}}`; errors never echo the offending value. The executor, the journal and the policy each normalize caller data before using it.
- `Policy.evaluate/2` normalizes both arguments first and denies with `{:intent, reason}` or `{:context, reason}`. A context decimal such as NaN now denies with `{:context, {:not_plain, [:quotes, symbol]}}` instead of `{:context, {:invalid, :quotes}}`. The untrusted-provenance prompt no longer calls `inspect` on the source: `(email)` rather than `("email")`, and `(news)` rather than `(:news)`.
- The policy file gains `advanced_orders`, `symbols_allow`, `symbols_deny`, `max_orders_per_minute` and `drawdown_halt`, and `order_types` accepts `:stop_limit` and `:stop_market`. Every key is still required, so a policy written by an earlier `mix raxol.broker.init` fails to load with `{:missing_key, :advanced_orders}`; rerun the task in an empty directory or add the keys with their defaults.
- `Raxol.Broker.Journal`, the hash-chained decision journal (#1177): one `Raxol.Agent.Journal.FileStore` journal opened with `chain: true, private: true` at `~/.raxol/broker/journal` (`$RAXOL_BROKER_JOURNAL` or `:path`), directories 0700 and files 0600; a symlinked, foreign-owned or shared directory is refused. Each decision is a group of records sharing a `group_id`: intent, policy context snapshot, verdicts (`:pre_review`, `:post_review`, each with the rule ids in force), review response, `{:approval, :approved | :declined, by}` for a human answer to an ASK, `{:placing}`, and a terminal order response (`:placed`, `:failed` or `:unknown`), DENY verdict, declined approval or close. `open_group/2` writes the intent and context before any review or order call, `append_to_group/2` adds records as they happen, and `append_group/1` writes a whole group in one Writer call with the same validation. Every record is synced before the call returns, and nothing may follow a group's terminal record.
- `{:placing}` is the write-ahead point for the order call: the journal prices the order from the group's own intent and context and refuses one it cannot price (`{:error, {:unpriced_order, reason}}`); an order response without it is refused (`{:not_placing, id}`), and after it only an order response or a close is accepted. A close after `placing` records an unknown outcome. Review and order responses are recorded as given, with floats written as decimal strings, so a real order is never refused for its response's shape.
- On start the journal verifies its chain in one pass. A damaged journal keeps the process up and answers every append and query with `{:error, {:journal_damaged, offset}}`. On a healthy one, a group left open by a crash is closed: DENY `crash_before_verdict` when it has no `placing` record, otherwise `crash_outcome_unknown`, which keeps counting because the order call may have gone out. `verify/1` re-walks the chain on disk (appends wait behind it) and marks the journal unusable on any result but `:ok`; arming (#1179) is expected to require it. The journal traps exits, closes its Writer on shutdown, links to a Writer it joined, and stops when that Writer dies, so its supervisor restarts it.
- Queries read an ETS index built on start and kept current: an order counts toward `today_notional(since)` and `orders_last_minute(now)` from the moment its `placing` record is written, at the notional recorded there, and stops only when its order response says `:failed`; cancels and groups that never reached `placing` never count, and the live and rebuilt indexes agree. `realized_pnl_today(since)` sums the broker-reported P&L of `append_fill/1` records. The exchange-day boundary is the caller's (a UTC instant), so the context builder (#1185) owns the New York calendar.
- `Raxol.Broker.Journal.Codec` round-trips `%Intent{}` and `%Policy.Context{}` through JSON (Decimals as exact strings, atoms only from fixed lists or existing atoms), so a later replay can re-run `Policy.evaluate/2`; verdict details are encoded one way. `Policy.notional/2` is now public; `placing` uses it to price each order once.
- `mix raxol.broker.replay --date YYYY-MM-DD [--journal PATH]` prints each group opened that UTC day in journal order: intent, context, every rule's verdict for each policy pass (`pass` before the denying rule, `not run` after it), review, approval, placing, order, and outcome (including `IN FLIGHT` and counted `UNKNOWN`), then that day's fills. Every line passes through one escape step, so control characters in recorded text (C0, DEL, C1) print as `\uXXXX` and invalid UTF-8 as `\xNN`. It reads without the writer lock and refuses a journal whose chain does not verify, naming the offset. The README documents what to do with a damaged journal.
- `Raxol.Broker.Executor`, the one order path (#1178): `run/3` opens the group, journals the pre-review verdict, calls the order's `review_*` tool, journals the review, re-runs `Policy.evaluate/2` with the review's warnings, and on ALLOW journals `placing` and calls the order tool through `Raxol.Broker.Executor.Place`, journaling the response as `:placed`, `:failed` (`isError`, a JSON-RPC parse, request, method or params error, or a client error that provably sent nothing) or `:unknown` (timeout, transport failure, any other error). Any review warning, or a review response that cannot be read, turns ALLOW into ASK (`:review_warning`); `{:ask, group_id, prompts}` parks the group until `approve/3` (re-reads the counters, journals the approval, re-runs the policy, then places), `decline/3` or `close/3`. A bad approver or reason raises in the caller and leaves the group parked. The review call runs in a task, so `parked/2` answers during it; a queued call whose caller has died is dropped, never dispatched.
  - The `:policy` start option (required, checked with `PolicyFile.validate/1`) replaces the context's `policy`; `today_notional`, `orders_last_minute` and `review_warnings` are replaced too. Quotes, positions, portfolio values and `market_session` stay caller-supplied until #1185.
  - The daily window is a rolling 24 hours back from the executor's clock. No caller input moves it; a trading calendar the executor owns is #1185's.
  - `:review_timeout`, `:place_timeout` and `:reconnect_ms` must be integers in 1..4_294_000_000 ms (headroom under the VM timer limit), otherwise the executor refuses to start with `{:invalid_timeout, key, value}`.
  - The executor monitors the journal and stops with `{:journal_down, reason}` when it goes down, because the claim lives in the journal's memory; its supervisor restarts it, the new one claims again and closes the groups left open. Callers waiting on it get an exit. A journal that is not running at start is `{:error, :journal_not_running}`.
  - Threat model: the BEAM cannot stop code that deliberately writes into another module's private state, e.g. `Process.put` into its slots or `:sys.replace_state`. The guarantee is that no path through public APIs can send an order tool without the executor's review pipeline; every remaining bypass requires impersonating the executor's private process-dictionary slots on purpose.
  - Any journal or review error before `placing` means no order. Once the order call is made the result is `{:ok, map}`; `journaled: false` with `journal_error` means the response could not be recorded.
  - `init` touches only the journal: it validates options, prepares the MCP session with `Port.MCP.prepare/2` (a live session still fails start with `:live_port_in_dry_run`), resolves and monitors the journal, claims it, puts the receipt key in its process dictionary only after the claim, and closes the groups left open. The session connects after `init` without blocking the executor (`Port.MCP.start_client/1`, `Port.MCP.await_ready/2`); until it is ready `run/3` and `approve/3` return `{:error, :port_not_ready}` and open nothing, and `Executor.await_port(server, timeout \\ 30_000)` returns `:ok` or `{:error, :port_not_ready}`; a timeout above 4_294_000_000 ms is `{:error, {:invalid_timeout, :await_port, timeout}}` and the executor stays up.
  - On a failed connect or a dead session the executor stays up, logs it and reconnects after a backoff (`:reconnect_ms`, default 1_000, doubling to 60_000, reset once ready). A down endpoint never restarts the executor, so it cannot exhaust the supervisor's restart budget, and a session client that dies while connecting (for example a resolver that raises) is handled the same way instead of crashing the executor. The executor no longer replies `{:error, {:port_down, reason}}` itself; `{:port_down, reason}` remains a `Port.call/4` error and appears inside `{:review_failed, ...}` and in `:unknown` order responses.
  - A port that goes down after the review but before the place closes the group as `port_not_ready` without writing `placing`; `run/3` and `approve/3` return `{:error, :port_not_ready}`, and a re-run of the same intent places once the port is back. `Port.call/4` with a nil port returns `{:error, :port_not_ready}`.
  - No caller code runs in the executor process. `run/3` normalizes the intent and context (`Intent.normalize/1`, `Policy.Context.normalize/1`) in the caller and again inside the executor before anything else; a failure is `{:error, {:invalid_intent, reason}}` or `{:error, {:invalid_context, reason}}` with nothing journaled or sent. An unrecognised call is `{:error, :unknown_request}`. `:journal` must be an atom (a registered name) or a pid, anything else (`{:via, mod, name}`, `{:global, name}`) is `{:invalid_journal, value}`, checked first. `:clock` runs in a short-lived Task with a 5 s budget; a clock that is not a zero-arity fun is `{:invalid_clock, value}` at start, and one that crashes or returns anything but a UTC `DateTime` fails the call with `{:error, {:context, reason}}` and sends nothing. The clock's result passes `Raxol.Broker.Plain.normalize/1` and must come back as an ISO-calendar `Etc/UTC` `DateTime` with zero offsets, otherwise the call is `{:error, {:context, {:invalid_clock, _}}}` with no group and no tool call, so a forged calendar module never runs in the executor.
  - `Executor.child_spec/1` sets `shutdown` to the place timeout plus 5_000 (35_000 with the defaults), or to the `:shutdown` start option (a positive integer; anything else raises `ArgumentError`). A stop during a place waits up to that bound for the order call; a review in flight is not waited for. Journal writes are bounded separately by `:write_deadline`, so a journal stall that outlasts the bound ends with the executor killed and the group closed on restart as `crash_outcome_unknown`, which keeps counting and is never placed again.
  - Queued callers are monitored and dropped on `:DOWN`; the executor never calls `Process.alive?/1`, which raises on a remote pid. At most one queued run or approve is dispatched per callback and the rest are re-queued through a `:drain` message, so one callback never runs two place calls and the child spec's shutdown bound covers the place in progress; a new call never jumps ahead of queued ones. A `:drain` that arrives while a run is in progress is ignored, since the run re-sends one when it finishes.
  - Terms that come from other processes (call arguments, messages, exit reasons, values from caller-supplied funs) never run a protocol inside the executor or the journal: every `inspect` of one uses `structs: false`, an unexpected message is logged by its tag atom only, and a structure test fails the build on `inspect/1`, or `inspect/2` without a literal `structs: false`, in `Raxol.Broker.Executor*` and `Raxol.Broker.Journal`.
  - A place whose order session client is already dead (`{:port_down, {:noproc, _}}`, also nested in a `GenServer.call` exit) was never sent, so it is recorded as `:failed` with `not_sent: true` and the intent may be placed again. Any other `port_down` reason stays `:unknown`.
- `Raxol.Broker.Executor.Place` is the only module naming an order tool (`place_equity_order`, `cancel_equity_order`), enforced by a test. It refuses without an opaque `Raxol.Broker.Executor.ReviewReceipt` (HMAC-SHA256 over a fingerprint of the whole intent, the group id and a nonce), verified under the key the executor generates at start and keeps in its own process dictionary; `Place` takes no key from its caller, so in any other process every receipt is `{:error, :invalid_receipt}`. Each place sends `ref_id`, a UUID derived from the intent id; an intent id with a `placing` whose outcome is not `:failed` returns `{:ok, :duplicate}` without a call, across restarts (`Raxol.Broker.Journal.placing_for_intent/2`).
- `Raxol.Broker.Journal.claim/1`: one executor per journal. Only a process started as an executor may claim (`{:error, :not_an_executor}` otherwise); a starting executor claims the journal and a second gets `{:journal_claimed, pid}`. While a claim is held only the claimant may write any group record (`open_group`, `append_to_group`, `append_group`, every entry type); another process gets `{:error, {:not_claimant, id}}` (`id` nil for `open_group` and `append_group`), and with no claim held group writes are `{:error, :unclaimed}`, with nothing written either way. `append_fill` is unchanged. The journal refuses `placing` for a group without a review and an ALLOW or approval after it, and for an intent that already has a live `placing` in another group.
- Order tools go through `Raxol.Broker.Executor.Port`, a write-capable session separate from the read-only `Raxol.Broker.MCP.Client`; `Port.MCP` wraps an unregistered `Raxol.MCP.Client`. Only `mode: :dry_run` runs, and the session must carry `sandbox: true` and a URL that is not on `robinhood.com`, or it is refused as live before connecting; `mode: :armed` is `{:error, :not_armed}` until arming (#1179). Only equity orders and cancels are mapped until #1174.
- `Raxol.Broker.Journal.open_group/4` takes `mode:`, stored on the intent record and shown by replay; `open_groups/1` lists groups without a terminal record, which a starting executor closes as `executor_restarted`.
- Depends directly on `raxol_mcp`, `mint`, `castore`, `req` and `jason`.
- Every `Raxol.Broker.Journal` write (groups, fills, start-up crash closes) calls the new `Raxol.Agent.Journal.FileStore.append_many/3` with the journal's `:write_deadline` (default 60_000 ms, a positive integer up to 4_294_967_295, otherwise the journal refuses to start with `{:journal_open_failed, :invalid_write_deadline}`) instead of the Writer's default 5 s. A Writer that misses the deadline is never answered with `{:error, _}`, because its write could still land: the journal kills the Writer, waits for it to die and stops with `{:writer_stalled, ms}`, every waiting caller exits, and the executor stops with `{:journal_down, {:writer_stalled, ms}}`; a run waiting on it gets `{:error, {:journal_down, _}}`, and a stall at or before `placing` sends nothing. The kill does not promise that nothing lands: a dirty IO NIF already running can still finish the write. Recovery reads the disk, not the journal's memory, so on restart the disk decides: a `placing` that reached it closes as `crash_outcome_unknown` and keeps counting, one that did not leaves its group closed as `crash_before_verdict`. A fsync slower than the deadline therefore costs a restart rather than hanging every order and cancel behind it.
- The journal checks the claimant before it reads anything a group write carries, then rebuilds a new group's intent and context with `Intent.normalize/1` and `Policy.Context.normalize/1` before encoding them. A non-claimant's struct is refused untouched (`{:error, :unclaimed}` or `{:error, {:not_claimant, nil}}`), and a claimant's non-plain data is `{:error, {:invalid_intent, reason}}` or `{:error, {:invalid_context, reason}}` with nothing written, so no caller Enumerable or Inspect implementation runs in the journal. An unexpected message is logged with `inspect(message, structs: false)` for the same reason.
