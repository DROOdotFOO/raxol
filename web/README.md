# raxol.io

The Phoenix app behind [raxol.io](https://raxol.io): Raxol's browser surface,
serving the same `Raxol.Playground.Catalog` the terminal playground serves.

It depends on the working tree, not on Hex (`{:raxol, path: ".."}` plus
`raxol_agent` and `raxol_payments` from `../packages/`), so a change in the
framework shows up here on the next compile. Deployment lives in
[../docs/deployment/FLY_IO.md](../docs/deployment/FLY_IO.md).

## Routes

Defined in [lib/raxol_playground_web/router.ex](lib/raxol_playground_web/router.ex).

Pages, through the `:browser` pipeline:

| Path | Module | What |
| ---- | ------ | ---- |
| `/` | `LandingLive` | One screen, no scrolling. The hero plays committed frames of a real `Raxol.Headless` session and lets a visitor switch between four examples. No live session runs here. |
| `/playground` | `PlaygroundLive` | The interactive playground: catalog sidebar, a demo hosted through `TEALive`, code snippet, theme selector, multi-user presence. |
| `/gallery` | `GalleryLive` | The catalog index, filterable by category and complexity, each card carrying its committed preview. |
| `/replay` | `ReplayLive` | The one page that reads a real recorded session. Loads the committed asciicast below, builds a `Raxol.Recording.Index` once per node, and answers each scrub step by replaying the emulator forward from the nearest keyframe. Seeking is server-side here, unlike the frame players, because a `.cast` has no frames to reveal. |
| `/demos/:demo` | `DemoLive` | One demo per page, running the real catalog demo app through the lifecycle bridge. 30-minute idle timeout. |
| `/surfaces` `/ssh` `/agents` `/coding-agent` `/payments` `/token` | `TopicLive` | The deep dives the landing page used to stack, one topic per route. Listed individually rather than as `/:topic` so an unknown path 404s in the router. |
| `/demos` | `RedirectController` | 301 to `/gallery`, which is the index now. |
| `/repl` | `RedirectController` | 301 to `/playground`. |

Raw endpoints, with no session, no layout and no CSRF:

| Path | Module | What |
| ---- | ------ | ---- |
| `/health` | `HealthController` | PubSub, memory and SSH checks. Only a dead PubSub or critical memory answers 503, so a memory warning or an absent SSH extra does not take a machine out of rotation. |
| `/install` | `InstallController` | `scripts/install.sh` as text, for `curl -fsSL https://raxol.io/install \| bash`. Embedded at compile time and served `no-cache`, because it is executable content. |
| `/skill.md` | `SkillController` | The agent onboarding skill file from `priv/static/skill.md`. |
| `/examples/:example` | `ExampleController` | The four landing-hero modules as files that run, each with the two lines that start it. The whole segment is the param because Phoenix allows no suffix after one, so the URL is the filename you save it as. |
| `/llms.txt` `/llms-full.txt` | `CapabilitiesController` | Project summaries for LLMs, from `priv/static/`. |
| `/.well-known/raxol.json` `/api/capabilities` | `CapabilitiesController` | Machine-readable capability manifests, derived from `RaxolPlayground.Capabilities` so they cannot restate surfaces, packages or backends. |

## Running it locally

```bash
cd web
mix deps.get
mix phx.server        # http://localhost:4000
```

The first boot downloads the esbuild and tailwind binaries and compiles the
raxol umbrella, so it is slow once and warm afterwards. `RAXOL_DEV_SMOKE=1`
skips both asset watchers and moves the port to `$PORT` (default 4010), which
is what CI's dev-boot smoke step uses.

## Recorded frames

The landing hero and the gallery cards are not live sessions. They are terminal
frames rendered by real `Raxol.Headless` runs through
`Raxol.LiveView.TerminalBridge.buffer_to_html/2`, committed under `priv/` and
embedded at compile time by
[lib/raxol_playground/recorded_frames.ex](lib/raxol_playground/recorded_frames.ex),
so the dead render before the LiveView socket connects already carries frame
one and every gallery preview.

Generated by [../scripts/gen_landing_frames.exs](../scripts/gen_landing_frames.exs),
which must run from this directory:

```bash
cd web && mix run ../scripts/gen_landing_frames.exs
```

It writes, per hero example (`halo`, `harness`, `pulse`, `settle`):

- `priv/hero_frames/<example>/frame_NN.html`, the terminal pane
- `priv/hero_frames/<example>/ansi_NN.ansi`, the same buffers as the bytes the
  SSH surface writes, one per frame, so the two panes step in lockstep
- `priv/hero_frames/<example>/interval_ms`, the tick the frames were sampled
  at, which is what the page plays back at
- `priv/hero_frames/<example>/surface.mcp.json`, frame zero as the widget tree
  the MCP surface serves

and one preview per catalog demo under `priv/demo_previews/`: `<slug>.html` for
a static demo, `<slug>/frame_NN.html` for an animated one.

`--check` is a drift gate, not a dry run. It re-records into a scratch
directory and diffs against what is committed, so a difference means a source
change nobody re-recorded:

```bash
cd web && MIX_ENV=dev mix run ../scripts/gen_landing_frames.exs --check
```

`MIX_ENV=dev` is load-bearing: the committed artifacts are recorded under dev,
and a different env is a different render config that reports false drift. The
generator drives each demo's own interval message explicitly instead of
sleeping, which is what makes the gate possible at all; a generator whose
output moves on its own can never answer whether its artifacts are stale.
`beam_dashboard` is exempt by name and reported, because it renders the live VM.

Frames are committed, so rerun the generator when a hero example or a demo's
first render changes.

## The recorded session

`/replay` does not play frames. It reads one committed asciinema v2 file,
`priv/recordings/tour.cast` (9.8 KB, 34 repaints and 3 keystrokes over 4.0
seconds at 72x12), and reconstructs the screen at a scrubbed instant through
`Raxol.Terminal.Emulator`.

Generated by [../scripts/gen_replay_recording.exs](../scripts/gen_replay_recording.exs),
which also runs from this directory:

```bash
cd web && mix run ../scripts/gen_replay_recording.exs
cd web && MIX_ENV=dev mix run ../scripts/gen_replay_recording.exs --check
```

It drives a real `Raxol.Headless` session and writes each frame as the bytes
`Raxol.Core.Runtime.Rendering.Backends.build_terminal_frame/4` emits, which is
what a live recorder receives from the terminal backend. The timestamps come
from the application's own tick rather than from a wall clock, which is what
makes `--check` a drift gate rather than a guaranteed diff.

## Tests

```bash
cd web && MIX_ENV=test mix test
```

The suite covers the capability endpoints, the landing invariants (the install
command, the SSH banner, the fee table against the real fee schedule), a house
style guard for defects that already shipped once, per-route canonical URLs and
titles, the frame transport, and the one dev-only config pair that broke every
dev request when it went missing (`listeners: [Phoenix.CodeReloader]`).

CI runs this suite, the `--check` drift gate and a real `mix phx.server` boot in
`.github/workflows/web-deploy-check.yml`.
